## 0. 이번 묶음의 원칙

1. **부수 기능이 본체를 망가뜨리지 않는다.** 채팅·게시판(§7)은 Web UI 전용이며, 꺼도 질의·빌드·MCP 가
   그대로 동작해야 한다 → 토글 하나로 완전히 끌 수 있게 하고, 실패해도 다른 화면을 막지 않는다.
2. **설정은 전부 파일로.** 새 값(보관 기간, 폰트 증가 주기, 타임아웃 …)은 `config.json`·`server.json`·
   전용 파일에 두고 `setup/` 에 예시를, 문서에 설명을 남긴다. 코드 상수로 두지 않는다.
3. **권한은 기존 표를 쓴다.** 새 엔드포인트마다 등급(read/run/edit/index/rebuild/admin/destructive)을
   정하고 `security.json permissions` 로 바꿀 수 있게 한다. 별도 확인 대화상자를 새로 만들지 않는다.
4. **되돌릴 수 있게.** 저장 위치를 새로 만들 때는 보관 한도와 정리 명령을 같이 만든다.

## 1. 지난 요청 이력과 결과 다시 보기

### 1.1 지금 있는 것과 없는 것

| | 지금 |
|---|---|
| 저장 | `requests` 테이블(`store.py`)에 요청마다 `kind·summary·ms·config·result·trace·origin·run_id`. 보존은 `keep_requests`(기본 2000) 행 |
| 사용자 | **컬럼이 없다.** `origin` 에 `"web kh82.kim"` 처럼 출처와 사용자가 **한 문자열로** 들어간다 → 내 요청만 걸러내기 어렵다 |
| 화면 | Observability › Requests 탭(목록·상세), 진행 중 작업 보드(실행/대기) |
| 빠진 것 | ① 내 요청만 보기 ② 대기/진행/완료를 한 목록에서 ③ 클릭하면 **그때 나온 답변 화면 그대로** 보기 ④ 결과 원본을 DB 밖에 따로 보관 |

### 1.2 결정

- **`requests` 에 `user` · `status` 컬럼을 추가**한다(기존 DB 는 `ALTER TABLE` 로 이관, 값이 없으면 `origin` 에서 뽑는다).
  - 대안 A: `origin` 문자열을 파싱해서 쓴다 → 사용자 이름에 공백이 있으면 깨지고, 인덱스를 못 건다. **버림**.
  - 대안 B: 별도 테이블 `request_owner` → 조인 비용만 늘고 얻는 게 없다. **버림**.
- **결과 본문은 파일로 따로 보관**한다 — `data/requests/<yyyy-mm>/req_<id>.json`(설정 `requests_dir`).
  - 이유: `result`/`trace` 가 요청당 수십~수백 KB라 DB 가 빠르게 커지고, `keep_requests` 로 잘리면
    **사용자가 "그때 그 답"을 다시 못 본다**. 파일로 두면 DB 는 목록용으로 가볍게 유지하고
    보관 기간은 파일 쪽에서 따로(더 길게) 가져갈 수 있다.
  - DB 에는 목록에 필요한 것만 남기고, 상세 조회는 **파일 우선 → 없으면 DB** 로 읽는다(예전 요청 호환).
  - 정리: `requests_keep_days`(기본 90) 를 넘은 파일은 스케줄러 청소 작업이 지운다.
- **화면**: Ask 탭에 "내 지난 요청" 패널을 둔다(진행 중 작업 보드와 같은 자리 계열). 한 줄을 누르면
  **Ask 의 결과 영역에 그때의 답변·근거·판정·프로파일을 그대로** 렌더한다(질의를 다시 돌리지 않는다).
  Observability › Requests 는 관리자용 전체 목록으로 남긴다.
- **권한**: 내 요청 = `read`. 다른 사람 것까지 보기 = 기존 `monitor.show_user_to_viewer` 와 같은 계열의
  새 등급이 아니라 **작업 등급 `run`**(기본 class3) 이상이면 전체 목록을 볼 수 있게 하고,
  `security.json permissions.ops` 로 조직마다 바꾸게 한다.

### 1.3 겸사겸사 고칠 것 (멍키 테스트에서 나온 관찰)

`/api/activity` 가 보고하는 대기열과 `queue_max` 검사가 세는 대기열이 어긋난다
([VERIFICATION_0916.md](VERIFICATION_0916.md) §2.6). 같은 집합을 보게 맞추고, 클라이언트가 끊긴 요청은
목록에 드러내 관리자가 "왜 바쁘다고 하는가" 를 볼 수 있게 한다.

## 2. Settings › 모델·프로바이더 화면

### 2.1 확인한 사실

- 선택 가능한 모델은 **이미 `models.json` 카탈로그**에 있다(`id·provider·label·roles[]·tags·context_k·enabled`).
  `roles` 가 비면 모든 역할에 표시된다. CLI `models catalog add|remove`, Web Settings › 모델 하단에서 편집한다.
- 화면은 `/api/models` 로 **현재 설정값을 읽어서** 그린다. 다만 탭을 처음 열 때만 그리므로
  "새로 고치면 다시 읽는다" 는 보장이 약하다.
- **역할 LLM** 은 카탈로그 드롭다운을 쓰지만, **임베딩 모델은 `datalist` 자동완성 입력**,
  **리랭크 API 모델은 그냥 텍스트 입력**이라 "무엇을 고를 수 있는지" 가 화면에 안 보인다.

### 2.2 결정

- 모델 탭을 **열 때마다 현재 설정을 다시 읽는다**(탭 전환·새로고침 모두). 더해서 **↻ 설정 다시 읽기** 버튼을
  명시적으로 둔다(파일을 밖에서 고친 뒤 확인하는 용도).
- `models.json` 카탈로그에 **`kind`** 를 명확히 쓴다: `llm`(기본) · `embed` · `rerank`.
  임베딩·리랭크 모델도 카탈로그 항목으로 관리하고, 화면은 **같은 드롭다운 컴포넌트**로 그린다.
- 화면에 **"지금 실제로 쓰이는 모델" 표**를 역할별로 모두 보여 준다 — answer/expand/rerank/verify/summary/
  extract/review/forensic + **embed** + **rerank(API)** 까지 한 표에. 값의 출처(역할 설정 → 전역 → 자동)를 함께 표시한다.

## 3. 답변 페르소나 — 모뎀 PHY 임베디드 개발자를 위한 답변

`prompts/answer_guide.md`(역할 프롬프트)를 다시 쓴다. 요구: **통신 지식 + SW 지식을 동시에 요구받는
모뎀 physical layer 개발자**에게 쓸모 있는 답, **근거를 빠짐없이 쓰고 지어내지 않으며 구조화된** 답,
**약한 모델에서도** 지켜지는 형식.

- 약한 모델 대책: 지시를 **짧은 명령문 목록**으로, **출력 뼈대를 그대로 제시**, 금지 사항은 "하지 마라" 대신
  **무엇을 쓸지**로 적는다. 예시를 하나만 두되 코드펜스로 감싸 본문과 섞이지 않게 한다.
- 근거 누락 방지: "모든 문단에 `[C#]`", "근거에 없는 수치·ID 는 쓰지 않는다", "근거가 모자라면 **모자란다고 적는다**".
- 파일로만 바꿀 수 있어야 한다 — 코드에 문장을 넣지 않는다.

## 4. 규칙 파일(`query_rules.json` · `data/rules.json`)의 확장성

사용자가 겪은 문제: **acronym 으로 치환된 단어가 synonym 에 있으면 동작하지 않았다** — 즉 규칙 종류가
서로를 모르고 한 번만 적용된다. 그리고 `graph_rules.py` 에 하드코딩된 부분이 있어 확장이 어렵다.

- 확장 규칙을 **여러 번 접어 적용(fixed point)** 하되 상한을 둔다(`query_rules_max_rounds`).
- 규칙 간 **중복·순환**을 탐지해 경고로 보고한다(`rules lint`).
- 그래프 규칙을 파일(`data/rules.json`)로 더 많이 내보내고 코드에는 해석기만 남긴다.
- 모뎀/임베디드 기본 사전(약어·동의어·복합어·ID 패턴·관계 규칙)을 **예시 파일**로 제공한다.

## 5. 기본값과 Web UI 버튼

- `precompute` · `query_cache` 토글의 **기본값을 off** 로 (`config.json` 과 `config.py` 의 기본 둘 다).
- 새로 추가한 버튼(복사·펼치기·접기 계열)이 실제로 동작하는지 **눌러서** 확인한다.

## 6. opencode headless 무응답 대책

- 재시도·타임아웃·백오프는 이미 역할별로 있다(`agents.json`, `llm_retries/llm_timeout`). 부족한 것은
  **무응답을 빨리 알아채는 것**과 **무슨 일이 있었는지 남는 기록**이다.
- 조용한 실패(빈 응답·부분 출력)를 실패로 판정, 진행이 없으면 중단하는 **무출력 감시(stall timeout)**,
  실패 시 **요청/응답 일부를 로그와 `llm_report` 에** 남기고 Web 배너로 올린다.

## 7. 협업 — 휘발성 채팅 + 게시판

- 채팅은 **휘발성**(서버 메모리, 보관 시간 설정). `/게시` 로 올린 것만 **게시판**에 남는다.
- 게시 시 **내 최근 작업 목록**을 보여 주고 요청 하나에 연결할 수 있게 한다(§1 의 이력과 연결).
- 말풍선은 **드래그로 옮기는 캐릭터 아이콘 위**에 뜬다. 머문 시간이 길수록 글씨가 커진다
  (시작 크기·증가 주기는 **관리자 설정**).
- 위치는 **왼쪽 사이드바 최상단 고정**, 프리셋은 그 아래로 내려간다. 접으면 최근 한 줄만.
- **본체에 영향 없음**: 토글 `collab` 하나로 끄고, 저장은 별도 파일, 실패해도 다른 화면을 막지 않는다.
