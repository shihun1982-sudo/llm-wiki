# 문서 재배치 — 현행 / 기록 분리 (2026-09-20)

> 이 문서는 **그날의 결정 기록**이다. 지금의 배치 규칙과 읽는 순서는 [DOC_MAP.md](../../DOC_MAP.md) 를 본다.

## 1. 요청

> *"docs 안에 날짜 폴더를 만들어서 관리하는 게 더 깔끔하지 않아? 그래야 어떤 게 최신인지 알 수 있고 …
> 결국 필요한 건, 모든 문서를 최신 버전으로 상세히 정리하고 싶은 거야. 예전 문서 정보는 잘못된 정보도
> 많고 하니, 최신 정보 기준으로 각 종류의 문서를 상세히 정리해서 보고 싶은 거야."*
> 이어서: *"내가 한 제안들은 너도 최신 트렌드 고려해서 충분히 고민하고 구현 진행해줘."*

## 2. 조사한 사실

당시 `docs/` 에 문서 68개가 평평하게 있었고, 성격이 전혀 다른 둘이 섞여 있었다.

| | 개수 | 예 |
|---|---|---|
| 현행 — 기능·절차·구조 | 42 | `SECURITY.md` · `BRINGUP_GUIDE.md` · `MCP.md` |
| 기록 — 계획·검증·리뷰 | 26 | `IMPLEMENTATION_PLAN_0918.md` · `VERIFICATION_0917.md` · `CODE_REVIEW_0917.md` |

참조 관계를 실제로 세어 보니 비대칭이 컸다 — 코드·설정 예시·README 가 **현행 문서**를 100곳 넘게
가리키는 반면, **기록 문서**를 가리키는 코드는 18곳뿐이었다.

그리고 현행 자리에 있으면서 이름에 날짜가 박힌 문서가 둘 있었다: `SURFACE_AUDIT_0920.md`(실은 현행)와
`VERIFICATION_0918.md`(실은 기록인데 `verify_all.py` 가 **최신 결과 표를 거기에 덮어쓰고** 있었다 —
그날의 사실을 담은 문서가 매번 갱신되고 있었던 셈이다).

## 3. 검토한 안과 택한 것

| 안 | 장점 | 단점 | 결론 |
|---|---|---|---|
| **A. 전부 날짜 폴더** (`docs/2026-09-20/…`) | "언제 것" 이 폴더로 보인다 | ① 주제마다 "최신은 어느 폴더?" 를 매번 찾아야 한다 ② 회차마다 전 문서를 복사하면 낡은 사본이 폴더 수만큼 쌓이고, 복사하지 않으면 현행이 여러 폴더에 흩어진다 ③ 현행을 옮기는 순간 코드·예시의 `docs/X.md` 참조 100곳이 깨진다 | **기각** |
| **B. `docs/current/` + `docs/history/`** | 경계가 이름으로 명확 | 현행을 옮기는 비용(③)은 A 와 같다. 얻는 것은 이름뿐 | 기각 |
| **C. 루트 = 현행 · `docs/history/<날짜>/` = 기록** | 규칙 한 줄("docs 바로 아래면 지금") · 참조 18곳만 수정 · 평평한 현행은 Diátaxis/docs-as-code 관행 그대로 | 기록을 옮길 때 한 번 정리 필요 | **채택** |

**최신 트렌드를 어떻게 반영했나.** 날짜/버전 폴더는 *여러 제품 버전을 동시에 서비스할 때* 쓰는 장치다
(Docusaurus·mkdocs 의 versioned docs). 여기는 사내에 한 벌만 돌아 그 전제가 없다. 반대로 **결정 기록을
날짜 찍어 불변으로 두는 것**은 ADR(Architecture Decision Record)의 표준 관행이고, 이 저장소의 계획·검증
문서가 정확히 ADR 의 역할을 한다. 그래서 **"현행은 평평하게 · 기록은 날짜로"** 라는, 두 관행을 각자
맞는 자리에 쓰는 배치를 택했다.

이 판단은 이 저장소가 이미 내렸던 결정과도 같은 방향이다 — [PORTING.md](../../PORTING.md) 에서 설정
파일을 한 폴더로 "옮기지 않고 가리킨다" 고 한 이유(옮기면 기존 경로가 전부 깨진다)와 동일하다.

## 5. 규칙이 말로만 남지 않게 — `verify_docs.py` 에 더한 검사

| 검사 | 무엇을 막나 |
|---|---|
| 현행 자리에 **날짜 붙은 파일 이름** 금지 | 시간이 지나면 다시 섞인다. 이름이 규칙을 강제한다 |
| 기록 문서가 **회차 색인에 있는가** | 색인에 없는 기록은 아무도 못 찾는다 |
| 모든 CLI 명령·MCP 도구·설정 키가 **현행 문서에 설명돼 있는가** | 기능을 만들고 문서에 안 적는 것. 기록 문서에 적힌 것은 "예전에 있었다" 일 뿐이라 세지 않는다 |
| 모든 하네스가 `tools/verify/README.md` 목록에 있는가 | 목록에 없으면 아무도 돌리지 않는다 (켜 보니 25개 중 **14개가 빠져 있었다**) |
| `<!--live:키-->` 로 표시한 규모 숫자 | 현행 문서의 "지금 N개" 가 낡는 것. 표시가 없으면 검사하지 않으므로 기록은 자동 제외 |

### 왜 숫자를 "표시" 하게 했나

처음에는 `"CLI 명령 (\d+)개"` 같은 **문장 패턴**으로 잡으려 했는데 산문까지 걸렸다 —
"표 밖에 있던 CLI 명령 3개" 는 총계가 아니다. **그 숫자가 총계인지 아닌지는 글쓴이만 안다.**
그래서 선언하게 했다: `CLI 명령 <!--live:cli-->48개`. HTML 주석이라 화면에는 보이지 않는다.
