# BUILD_UNDER_LOAD — 사람들이 쓰는 중에 빌드해도 되나 (30명 기준 실측)

  대상: 30명 정도가 함께 쓰는 서버를 운영하며 코퍼스를 갱신해야 하는 사람.
  결론부터: **증분 빌드와 채널 빌드는 그냥 돌려도 된다. 전체 리빌드만 서비스를 멈춘다** — 그리고 그 경우에도
  설정 한 줄로 멈추지 않게 할 수 있다(§3). 동시성 구조 전반은 [CONCURRENCY.md](CONCURRENCY.md),
  빌드 단계 자체는 [REBUILD_SPEC.md](history/2026-09-17/REBUILD_SPEC.md).

## 1. 실측 (2026-09-19)

`tools/verify/verify_build_load.py` — 30명이 계속 질의하는 동안 빌드를 걸고, **빌드가 도는 구간에
시작된 질의만** 추려 잰 값이다. 문서 600개·격리 환경·`hash` 임베더.

| 빌드 | 빌드 시간 | 빌드 중 질의 | p50 | p95 | max | 거절 | 실패 |
|---|---|---|---|---|---|---|---|
| 증분 | 1.2s | 265건 | 69ms | 154ms | 255ms | 0 | 0 |
| 채널 `fts` | 0.7s | 51건 | 44ms | 503ms | 531ms | 0 | 0 |
| 채널 `vector` | 0.6s | 130건 | 60ms | 142ms | 276ms | 0 | 0 |
| 채널 `graph` | 7.7s | 1,438건 | 73ms | 179ms | 1,271ms | 0 | 0 |
| **전체 리빌드** | **5.7s** | **54건** | **53ms** | **5,548ms** | **5,587ms** | 0 | 0 |

읽는 법:

- **증분·채널 빌드는 서비스에 거의 영향이 없다.** `graph` 채널 빌드는 7.7초나 걸리는데 그 사이
  1,438건이 평소 속도(p50 73ms)로 처리됐다. 읽기를 막지 않기 때문이다.
- **전체 리빌드는 다르다.** 5.7초 동안 들어온 질의가 **54건뿐**이고 p95 가 **5.5초** — 즉
  *빌드 시간 = 모든 사용자의 대기 시간*이다. 실패·거절은 0이지만(대기 한도가 900초라 끝까지 기다린다)
  사용자에게는 "사이트가 멈췄다" 로 보인다.
- **실패도 거절도 0이다.** 어떤 빌드에서도 질의가 깨지거나 부분 색인을 읽지 않았다. 빌드 뒤
  색인 무결성 점검(`build verify`)도 통과했다.

코퍼스가 크면 전체 리빌드 시간이 그대로 늘어나고, 대기 시간도 같이 늘어난다. 임베딩을 원격
프로바이더로 하면 특히 길다 — 그래서 §3 이 필요하다.

## 2. 왜 그런가 (락 정책)

| 작업 | 티켓 가중치 | 질의는 |
|---|---|---|
| 질의·검색 | `read` | 동시 8건 (`max_parallel_reads`) |
| 증분 빌드 · 채널 빌드 | `soft` | **계속 처리된다** (다른 *쓰기* 만 막는다) |
| 전체 리빌드 · 설정 저장 · 스냅샷 복원 | `exclusive` | 끝날 때까지 기다린다 |

읽기는 *쓰기가 기다리고만 있어도* 잠깐 멈춘다(쓰기 기아 방지). 그래서 채널 빌드에서도 p95 가
가끔 500ms 까지 튄다 — 락을 잡는 **순간**의 대기다. 빌드 전체 시간과는 무관하다.

## 3. 전체 리빌드 중에도 질의를 받으려면

`server.json`:

```jsonc
{ "concurrency": { "reads_during_build": "always" } }
```

| 값 | 뜻 |
|---|---|
| `never` | 증분 빌드 중에도 질의를 막는다 (가장 보수적) |
| `incremental` | **기본** — 증분·채널 빌드 중에는 질의 허용, 전체 리빌드는 배타 |
| `always` | 전체 리빌드 중에도 질의를 받는다 |

같은 조건에서 `always` 를 켜고 다시 잰 값:

| | 빌드 중 질의 | p50 | p95 |
|---|---|---|---|
| `incremental`(기본) | 54건 | 53ms | 5,548ms |
| **`always`** | **893건** | **54ms** | **376ms** |

**감수하는 것**: 전체 리빌드는 색인을 비우고 다시 채운다. `always` 면 그 사이 질의가
**아직 덜 채워진 색인**을 읽는다 — 답이 틀리는 게 아니라 "근거를 찾지 못했다" 가 늘어난다.
정확도보다 응답성이 중요한 시간대(업무 시간)에 쓰고, 야간 리빌드는 기본값으로 두는 식이 낫다.

  ⚠ **2026-09-19 이전에는 이 설정이 전체 리빌드에 동작하지 않았다.** 완화 분기가 `weight == "write"`
  만 보고 있었는데 전체/채널 리빌드는 `weight == "exclusive"` 로 들어와, 문서가 권하던 바로 그
  상황에서 무효였다. 위 실측이 그것을 드러냈고 `llmwiki/reqmgr.py` 에서 고쳤다.
  회귀 방지: `tests/test_build_concurrency.py`.

## 4. 권장 운영 (30명 기준)

| 상황 | 권장 |
|---|---|
| 문서가 몇 건 바뀌었다 | **증분 빌드** — 언제 돌려도 된다. 워처(`watch`)에 맡겨도 된다 |
| 한 채널만 다시 만든다 (규칙 변경 등) | **채널 빌드** `build graph|fts|vector` — 읽기를 막지 않는다 |
| 코퍼스를 통째로 바꿨다 | **전체 리빌드는 야간으로** ([SCHEDULER.md](SCHEDULER.md) 의 `at`+`days`) |
| 업무 시간에 전체 리빌드가 불가피하다 | `reads_during_build: "always"` + 공지. 끝나면 되돌린다 |
| 빌드가 도는지 사용자가 알아야 한다 | Web 관리 › **진행 중 작업** 에 진행률·ETA·중지 버튼이 뜬다 |
| 빌드가 너무 오래 걸린다 | `build fts` 는 `fts_trigram` 이 켜져 있어야 빠르다 ([REBUILD_SPEC.md](history/2026-09-17/REBUILD_SPEC.md)) · 임베딩은 `embed_batch` 조정 |

바꾸지 말 것:

- `read_wait_timeout_s`(기본 900초)를 크게 올리지 말 것 — 이 값은 *빌드* 가 아니라 *질의의 수명*이다.
  크게 잡으면 전체 리빌드 동안 질의 스레드가 쌓여 서버가 마비된다.
- `write_wait_timeout_s`(기본 48시간)를 짧게 줄이지 말 것 — 긴 빌드가 시작도 못 하고 503 이 된다.

## 5. 안전장치 (실수로 리빌드가 도는 것을 막는 것)

- 채널·전체 리빌드는 **admin 전용**이고, Web 에서는 **확인 문구 + 비밀번호 재입력**을 거친다.
  확인 없이 부르면 `428 Precondition Required` 로 막힌다 (위 하네스가 이것도 확인한다).
- 전체 리빌드는 색인을 비우기 전에 **자동 스냅샷**을 만든다 (`snapshot list|restore`).
- 빌드 전 `health` 가 코퍼스 경로를 확인한다 — 경로가 비어 있으면 **기존 색인을 지우지 않는다**.
- 빌드는 파일 락(`data/build.lock`)으로 프로세스 사이에서도 한 번에 하나만 돈다.

## 6. 검증

```bat
python tools/verify/verify_build_load.py --users 30            :: 기본 정책으로 실측 (26개 검사)
python tools/verify/verify_build_load.py --users 30 --policy always
python tools/verify/verify_build_load.py --users 30 --docs 2000 :: 더 긴 빌드로
python -m unittest tests.test_build_concurrency                :: 락 정책 회귀 (10건)
```

하네스는 `verify_all.py` 에 들어 있다. 검사 항목: 빌드 성공 · 질의 실패 0 · 질의 거절 0 ·
빌드 뒤 질의 정상 · 빌드 뒤 색인 무결성 · 확인 게이트가 막는가.
